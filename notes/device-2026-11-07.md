# Device evidence — cupid, 2026-11-07

Phone: Xiaomi 12 (`cupid`), serial `1cb22738`, PixelOS (AOSP) + KernelSU root,
kernel `5.10.269-PhoenyxCore.LTO.v3`, 8 cores, 4 KiB pages
(`ro.boot.hardware.cpu.pagesize=4096`). USB debugging enabled; commands run
through the Windows `adb` server (`C:\platform-tools\adb.exe`).

## Identity and boot

```
ro.board.platform      taro
ro.boot.hardware.sku   cupid
ro.boot.serialno       1cb22738
ro.boot.cpuid          0x0000043252a25a21
ro.boot.dtb_idx        10
ro.boot.dtbo_idx       19
ro.boot.hardware.revision GL_MP_2.19.0
ro.boot.secureboot     1

ro.boot.veritymode     enforcing

/sys/devices/soc0/soc_id     457
/sys/devices/soc0/machine    WAIPIO
/sys/devices/soc0/family     Snapdragon
/sys/devices/soc0/revision   2.2
```

`dtb_idx 10` is the Waipio v2 entry in the stock vendor_boot DTB table;
`revision 2.2` agrees. The firmware DTB must use the **v2** base.

## CPU / PAC capability

```
$ adb shell su -c 'grep -E "Features|CPU implementer|CPU part" /proc/cpuinfo'
Features : ... paca pacg dcpodp flagm2 frint i8mm bti
CPU implementer : 0x41
CPU part : 0xd46 / 0xd47 / 0xd48   (A510 / A710 / X2)
```

`paca` and `pacg` are present on every core: FEAT_PAuth address and generic
keys exist at EL0 capability level. This is **not** the arm64e gate: PAC key
writes at EL1 and `PACIA`/`AUTIA` trapping are still untested.

## Hypervisor

```
/sys/hypervisor/type     gunyah
/sys/hypervisor/version/api      1
/sys/hypervisor/version/variant  81
```

Gunyah runs at EL2. Whether it sets `HCR_EL2.APK`/`API` (which would trap the
EL1 PAC key registers and make arm64e impossible) can only be tested by booting
our image, not from Android userland.

```

start512 25362432

```

4096-byte LBA: first `3170304`, count `58357755`, last `61528058`.
`super` is `sda28` (8912896 512-byte sectors).

The device is still on PixelOS; this geometry is the PixelOS GPT, not the stock
HyperOS one. Re-measure after any re-partition.

## Live device tree

```
$ adb shell su -c 'cat /sys/firmware/devicetree/base/model'
Cupid based on Qualcomm Technologies, Inc SM8450
$ adb shell su -c 'cat /sys/firmware/devicetree/base/compatible'
qcom,waipio-mtp qcom,waipio qcom,mtp
```

`/sys/firmware/fdt` is mode 0400 but `cat` is denied even as root (SELinux
`u:r:ksu:s0`, `Enforcing`). `/sys/firmware/devicetree/base` is readable and
confirms the merged cupid identity.

## Panel

Kernel command line: `msm_drm.dsi_display0=qcom,mdss_dsi_l3_42_02_0a_dsc_cmd`,
matching the L3 42 02 0a 1080x2400 panel in the vendor device tree.

## Live FDT (pulled through MT Manager)

`/sys/firmware/fdt` is SELinux-blocked even for root, so the file was copied to
`/storage/emulated/0/Download/cupid-fdt/fdt` and pulled over adb.

```
size    773371 bytes
sha256  3d669081f48c6a810f0d95f7c5fa37d62dcb1c40a9d6fe4eb8b79bc24bebf7f0
model   Cupid based on Qualcomm Technologies, Inc SM8450
msm-id  0x1c9 0x20000 0x1e2 0x20000 0x1c9 0x10000 0x1e2 0x10000
board-id 0x10008 0x0
```

`scripts/build-cupid-dtb.sh` uses it verbatim when
`UNIXNU_CUPID_LIVE_FDT=/path/to/fdt` is set. Otherwise it compiles the
open-source waipio-v2 + cupid overlay and patches the same root identity
(451042 bytes, sha256 `7604f605…`). The open-source tree is missing the SDE
display controller nodes because the display overlay needs the
`waipio-sde-display` base; that is a display-milestone item, not a boot-image
blocker (SimpleFbDxe uses ABL's scan-out).

## Kernel config

`/proc/config.gz` is readable: `CONFIG_ARM64_PTR_AUTH=y`, `CONFIG_KVM=y`,
kernel cmdline `kvm-arm.mode=protected`, and `/sys/hypervisor/type=gunyah`.
Gunyah is the EL2 hypervisor here; whether it traps the PAC key registers is
still the first-boot gate.
